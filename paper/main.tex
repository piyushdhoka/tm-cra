\begin{abstract}
Removing whole Transformer blocks, known as depth pruning, is a simple way to shrink small instruction-tuned language models for edge and low-cost deployment, but it damages different capabilities by very different amounts, and the short fine-tuning run that follows, called healing, has a fixed token budget. Current practice spreads that budget uniformly over a generic mixture or in proportion to how damaged each capability is. We argue that the budget should instead follow how recoverable each capability is. Recoverability-aware healing fits, from a few cheap pilot runs, a recovery curve for every capability together with a transfer matrix that captures how data for one capability helps another, and then solves a small concave program that jointly chooses the data mixture and the adaptation scope inside a trust region that forbids extrapolation beyond the pilots. We evaluate six capabilities, namely structured output, function calling, instruction following, mathematical reasoning, safety refusal, and knowledge, on four model families with one to two billion parameters pruned by Block Influence, using three seeds and paired bootstrap tests. The order in which capabilities break is highly consistent across families, but damage does not predict recovery speed. At an equal budget, the proposed allocation is never worse than uniform healing on mean retention, raises the worst-retained capability by up to seventeen points on two families, reduces over-refusal on three, and beats damage-proportional allocation on two families while matching it on the other two. Pilot-free proxies and worst-case objectives did not work, and we report them as negative results. Code and all results are released.
\end{abstract}
